# Décisions techniques

Consigner ici les décisions qui affectent durablement l’architecture ou le travail de l’équipe. Une décision doit exposer le contexte et le besoin, les options étudiées, les critères, les compromis, le choix retenu et ses conséquences. Ajouter des sources lorsque des faits techniques, de sécurité ou de coûts l’appuient.

Utiliser un fichier par décision, avec un nom descriptif, par exemple `0001-choix-du-backend.md`. Ne pas inscrire comme décision une simple piste mentionnée dans le cadrage. Les décisions ouvertes sont recensées dans `docs/research.md` et `docs/architecture.md` jusqu’à leur arbitrage.

La décision de socle est enregistrée dans `0001-socle-technique.md`. Les choix de modèles, de versions, de quotas, de conservation et d’hébergement restent ouverts.
